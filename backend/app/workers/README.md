# Workers 异步任务说明

当前不引入 Celery：图片上传完成时，业务数据与图片处理任务在 PostgreSQL 中同事务写入。FastAPI 启动时运行图片 worker，按 `IMAGE_WORKER_CONCURRENCY` 控制并发（默认 2）；生产环境需结合 2C2G 主机资源评估并调整。

Worker 通过行锁领取任务，使用租约及续期协调多进程，失败后有限重试，最多尝试 5 次；进程重启后过期租约可重新领取。管理员可在图片管理的“处理任务”中查询并重试失败任务。处理采用至少一次语义，对象存储与数据库不具备跨系统原子性，仍需监控失败任务和孤儿文件。

课表 PDF 解析当前在 API 请求中同步执行，尚未迁入后台队列；部署时应评估上传大小、并发和资源限制。
